# The error did not go away. It moved.
### Two frontier models, a hidden chart, and the examination that never happened

**The experiment.** A language model plays the emergency physician. It sees one triage line and nothing else. It must ask the patient, name each examination manoeuvre, and order each test; a simulator with a hidden chart answers only what is asked. Two of the eight charts contain a second disease that the leading diagnosis does not predict: a *Staphylococcus aureus* endocarditis with a new aortic murmur, behind a septic knee and behind a spondylodiscitis, in a patient on a TNF inhibitor with a recent portal of entry.

**The result.** GPT-6 Astra (OpenAI API) and Claude Fable 5.1 (Claude Code sub-agents) reached the correct primary diagnosis in every consultation. In all twelve runs on the two endocarditis charts, neither model auscultated the heart or ordered an echocardiogram; Astra stopped at a median of seven actions with five unused. Given the same two patients as written records with the murmur in the text, both models found the endocarditis 14 times out of 14. Asked directly whether such a patient needs an echocardiogram, both said yes. The knowledge was there; the examination was not. On some forty-five written rheumatology scenarios (about 710 graded answers), Astra otherwise behaved like an adaptive clinician: it treated classification criteria as classification criteria, ran therapeutic trials, reconsidered diagnoses on non-response, refused to cycle biologics, and switched when objective inflammation appeared. Its one lapse on written text has the same shape: a 71-year-old with seronegative polyarthritis in whom malignancy was never raised, 0 of 8.

**The claim.** When clinical knowledge is formalised, the error moves from the answer to the account of the patient on which the answer is computed, and that account closes the moment the diagnosis becomes actionable. We propose a metric, adaptive clinical intelligence: the fraction of runs in which the examination is completed after the diagnosis is secured. Observed: 0 of 12 (exact 95% CI 0 to 26.5%).

## Reproduce
```bash
python3 -m pip install -r requirements.txt
export OPENAI_API_KEY=...        # never commit keys
git tag                           # results of record are at tag v1.0-submission; every script OVERWRITES its output file
python3 run_cases.py
python3 exp_abc.py && python3 exp_frame.py
python3 exp_axspa.py
python3 exp_psa.py && python3 exp_psa_long.py && python3 exp_psa2.py
python3 exp_mirror.py && python3 exp_pso.py && python3 exp_ed.py && python3 exp_narrative.py
python3 exp_loop.py
python3 exp_loop.py --cases L9_dactylitis_vs_trauma --out exp_loop_L9_astra.json
python3 exp_loop.py --cases L10_spondylodiscitis_vs_flare --out exp_loop_L10v2_astra.json
python3 exp_ed_murmur_vignettes.py && python3 exp_echo_question.py
python3 build_results.py && python3 build_docs.py && python3 make_fig1.py
python3 translate_texts.py && python3 translate_transcripts.py   # readable renderings (cached)
```
Fable 5.1 as doctor: from a Claude Code session, spawn one fresh sub-agent per consultation with the prompt in `fable_doctor_prompt.md`; the sub-agent drives the simulator with
```bash
python3 sim.py start <case_id> <run_id>
python3 sim.py act   <case_id> <run_id> "<one action>"
python3 sim.py final <case_id> <run_id> "DECISIONE FINALE: ..."
```
then grade with `python3 judge_fable.py --cases <case_id> --out <file>`. `sim.py` resumes an existing `<case_id>_<run_id>` session, so use fresh run ids.

Model behaviour drifts with vendor updates; the JSON files are the record of what these versions did on these dates. See `METHODS.md` for scoring, harness asymmetries and design limits.
